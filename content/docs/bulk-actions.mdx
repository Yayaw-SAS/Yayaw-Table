# Bulk Actions

The bulk actions system provides a powerful way to perform operations on multiple table rows simultaneously. When users select multiple rows, an elegant expandable menu appears at the bottom of the screen with options to edit, delete, or copy the selected items.

## Features

- **Expandable menu** inspired by modern design patterns
- **Smart bulk editing** with unique field protection
- **Confirmation dialogs** for destructive actions
- **Direct form access** for editing operations
- **Automatic state management** and cleanup
- **Smooth animations** with Framer Motion

## Basic Usage

The bulk actions system is automatically integrated into the `DataTable` component when you provide the necessary handlers:

```tsx
import { DataTable, useBulkEdit } from 'yayaw-table';

function ProductsTable() {
  // Setup bulk edit functionality
  const bulkEdit = useBulkEdit({
    tableId: 'products',
    formType: 'products-bulk',
    onSuccess: (updatedData, selectedRows) => {
      console.log(`Updated ${selectedRows.length} products`);
    },
    onUpdate: async (ids, data) => {
      return await api.bulkUpdateProducts(ids, data);
    },
  });

  const handleBulkEdit = (rows) => {
    bulkEdit.openBulkEdit(rows);
  };

  const handleBulkDelete = async (rows) => {
    const ids = rows.map(row => row.original.id);
    await api.deleteProducts(ids);
  };

  const handleBulkCopy = (rows) => {
    const data = rows.map(row => row.original);
    navigator.clipboard.writeText(JSON.stringify(data, null, 2));
  };

  return (
    <DataTable
      tableType="products"
      onBulkEdit={handleBulkEdit}
      onBulkDelete={handleBulkDelete}
      onBulkCopy={handleBulkCopy}
    />
  );
}
```

## Bulk Edit Configuration

### Creating Bulk Edit Forms

Use the `createBulkEditFormConfig` helper to automatically generate form configurations optimized for bulk editing:

```tsx
import { createBulkEditFormConfig } from 'yayaw-table';

// Base product form configuration
const baseProductConfig = {
  id: 'products',
  fields: [
    { type: 'text', name: 'name', label: 'Product Name' },
    { type: 'text', name: 'sku', label: 'SKU' },
    { type: 'number', name: 'price', label: 'Price' },
    { type: 'select', name: 'status', label: 'Status', options: [...] },
    { type: 'text', name: 'category', label: 'Category' },
  ],
  // ... other config
};

// Bulk edit configuration
const bulkConfig = createBulkEditFormConfig(baseProductConfig, {
  title: 'Bulk Edit Products',
  description: 'Edit multiple products at once. Only filled fields will be applied to all selected items.',
  uniqueFields: ['sku', 'productCode'], // Prevent bulk editing of unique fields
  excludeFields: ['createdAt', 'updatedAt'], // Additional fields to exclude
});
```

### Configuration Options

```tsx
interface BulkEditOptions {
  title?: string;           // Form title
  description?: string;     // Description shown at top of form
  excludeFields?: string[]; // Fields to exclude from bulk editing
  includeFields?: string[]; // Only include these fields (overrides excludeFields)
  uniqueFields?: string[];  // Fields that must remain unique
}
```

### Default Exclusions

The system automatically excludes common fields that shouldn't be bulk edited:

- **System fields**: `['id', '_id', 'createdAt', 'updatedAt']`
- **Unique fields**: `['email', 'username', 'sku', 'slug', 'code']`

## Form Behavior

### Smart Field Handling

- **Common values**: Fields with identical values across all selected rows are pre-filled
- **Optional fields**: All fields become optional in bulk edit mode
- **Empty fields**: Fields left empty will keep their current values
- **Unique fields**: Automatically excluded to prevent conflicts

### User Experience

1. **Selection**: User selects multiple rows in the table
2. **Menu appearance**: Expandable actions menu appears at bottom center
3. **Direct editing**: Clicking "Edit" opens the bulk edit form immediately
4. **Form interaction**: User modifies only the fields they want to change
5. **Batch update**: Only modified fields are applied to all selected items

<Callout type="info">
The bulk edit form shows a single description at the top instead of repeating instructions for each field, creating a cleaner interface.
</Callout>

## Custom Implementation

### Using the Hook Directly

For custom implementations, you can use the `useBulkEdit` hook directly:

```tsx
import { useBulkEdit } from 'yayaw-table';

function CustomBulkActions() {
  const bulkEdit = useBulkEdit({
    tableId: 'products',
    formType: 'products-bulk',
    onSuccess: (data, rows) => {
      // Handle success
      toast.success(`Updated ${rows.length} items`);
    },
    onUpdate: async (ids, data) => {
      // Custom update logic
      const response = await fetch('/api/bulk-update', {
        method: 'POST',
        body: JSON.stringify({ ids, data }),
      });
      return response.ok;
    },
  });

  return (
    <button onClick={() => bulkEdit.openBulkEdit(selectedRows)}>
      Edit Selected
    </button>
  );
}
```

### Custom Menu Component

You can also use the `BulkActionsMenu` component independently:

```tsx
import { BulkActionsMenu, useBulkActions } from 'yayaw-table';

function CustomTable() {
  const bulkActions = useBulkActions({
    table: tableInstance,
    onBulkEdit: handleBulkEdit,
    onBulkDelete: handleBulkDelete,
    onBulkCopy: handleBulkCopy,
  });

  return (
    <div>
      {/* Your table */}
      
      {/* Bulk actions menu */}
      {bulkActions.showBulkActions && (
        <BulkActionsMenu
          selectedRows={bulkActions.selectedRows}
          onBulkEdit={bulkActions.handleBulkEdit}
          onBulkDelete={bulkActions.handleBulkDelete}
          onBulkCopy={bulkActions.handleBulkCopy}
          onClose={bulkActions.closeBulkActions}
        />
      )}
    </div>
  );
}
```

## API Reference

### useBulkEdit

```tsx
interface BulkEditConfig<TData> {
  tableId: string;                    // Table identifier
  formType?: string;                  // Form type (defaults to tableId + '-bulk')
  onSuccess?: (data, rows) => void;   // Success callback
  onUpdate?: (ids, data) => Promise<boolean>; // Custom update function
}

interface BulkEditReturn<TData> {
  openBulkEdit: (rows: Row<TData>[]) => void;  // Open bulk edit form
  isBulkEditOpen: boolean;                     // Form open state
  closeBulkEdit: () => void;                   // Close form
}
```

### createBulkEditFormConfig

```tsx
function createBulkEditFormConfig(
  baseConfig: FormConfig,
  options?: BulkEditOptions
): FormConfig
```

### BulkActionsMenu Props

```tsx
interface BulkActionsMenuProps<TData> {
  selectedRows: Row<TData>[];              // Selected table rows
  onBulkEdit?: (rows: Row<TData>[]) => void;   // Edit handler
  onBulkDelete?: (rows: Row<TData>[]) => void; // Delete handler  
  onBulkCopy?: (rows: Row<TData>[]) => void;   // Copy handler
  onClose?: () => void;                        // Close handler
  className?: string;                          // Additional CSS classes
}
```

## Best Practices

### Security Considerations

1. **Protect unique fields**: Always specify unique fields to prevent conflicts
2. **Validate permissions**: Ensure users can only edit records they have access to
3. **Audit trail**: Log bulk operations for security and compliance
4. **Rate limiting**: Implement rate limiting for bulk operations

### Performance Tips

1. **Batch API calls**: Process multiple updates in a single request when possible
2. **Optimistic updates**: Update the UI immediately and handle errors gracefully
3. **Progress indicators**: Show progress for large bulk operations
4. **Limit selection size**: Consider limiting the number of items that can be selected

### UX Guidelines

1. **Clear feedback**: Always provide clear success/error messages
2. **Confirmation for destructive actions**: Require confirmation for delete operations
3. **Undo functionality**: Consider implementing undo for bulk operations
4. **Smart defaults**: Pre-fill common values when possible

<Callout type="warning">
Be careful when performing bulk operations on production data. Always test thoroughly and consider implementing a preview mode for large operations.
</Callout>
